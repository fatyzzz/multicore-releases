# MultiCore

Нативный VPN-клиент для **Windows x64** и **Linux x86_64**. Написан на Rust, интерфейс на Slint, без WebView и Electron.

Внутри работают два ядра: **Mihomo** (туннель, DNS, правила, группы) и **Xray** (транспорты, которых нет в Mihomo). Подписку, правила и серверы задаёт провайдер. Вы вставляете ссылку и нажимаете «Подключить».

Этот репозиторий — публичный канал релизов: здесь лежат сборки, контрольные суммы и документация. Отсюда же приложение забирает свои обновления.

## Что умеет

- **Подключение одной кнопкой — мгновенно.** Со службой MultiCore ядра готовы всё время, пока открыто приложение: подключение и отключение занимают доли секунды и не спрашивают права администратора. Пинги и реальный узел за «Автовыбором» видны ещё до подключения.
- **Режим без TUN (Windows).** Трафик идёт через системный прокси, права администратора не нужны. Через VPN пойдут только программы, которые уважают системный прокси.
- **До 16 подписок.** Активна одна, переключение в заголовке окна.
- **Маршруты и группы.** Пинг подсвечивается цветом, есть поиск по всем группам (`Ctrl+F`). Для «Автовыбора» показывается реальный узел, за которым вы сидите.
- **Данные провайдера.** Трафик и срок подписки, анонсы, логотип, ссылки на поддержку и личный кабинет.
- **Автообновление подписки.** При запуске и по интервалу, который задал провайдер.
- **Трей и автозапуск.**
- **Обновления приложения** из этого репозитория, с проверкой SHA-256.

## Установка

### Windows 10/11 x64

| Файл | Что это |
|---|---|
| `MultiCore-Setup-x64.exe` | Установщик. **Рекомендуется.** На первом экране выберите режим (см. ниже). Регистрирует ссылки `multicore://` и может добавить автозапуск. |
| `multicore-windows-x64.zip` | Портативная версия: распакуйте и запустите `MultiCore.exe`. Ссылки `multicore://` не регистрирует. |

> Сборки пока **не подписаны** сертификатом, поэтому SmartScreen может предупредить о неизвестном издателе: «Подробнее» → «Выполнить в любом случае». Сверить файл с опубликованной суммой можно по разделу [«Проверка файлов»](#проверка-файлов).

**Режим установки:**

- **Со службой (рекомендуется).** Один запрос прав администратора при установке. Программа ставится в `Program Files`, регистрируется служба MultiCore. Дальше подключение мгновенное и без UAC, обновления тоже ставятся без запросов.
- **Без службы.** Без прав администратора, в профиль пользователя (`%LOCALAPPDATA%\Programs\MultiCore`) — как в версиях 1.0.x. Режим без TUN (системный прокси) работает без прав, а для TUN Windows спрашивает права при каждом подключении. Службу можно доустановить позже: Настройки → «Мгновенное подключение».

Ставьте программу из-под учётной записи администратора: если ввести пароль администратора в окне UAC из-под обычного пользователя, автозапуск и ссылки `multicore://` запишутся в профиль администратора. Подробнее — в [«Как это устроено»](docs/how-it-works.md).

### Linux x86_64

| Дистрибутив | Файл | Установка |
|---|---|---|
| Debian 12+, Ubuntu 22.04+ | `multicore_<версия>_amd64.deb` | `sudo apt install ./multicore_<версия>_amd64.deb` |
| Fedora 43/44 | `multicore-<версия>-1.x86_64.rpm` | `sudo dnf install ./multicore-<версия>-1.x86_64.rpm` |
| Arch Linux | `multicore-<версия>-1-x86_64.pkg.tar.zst` | `sudo pacman -U multicore-<версия>-1-x86_64.pkg.tar.zst` |
| Любой | `MultiCore-<версия>-x86_64.AppImage` | `chmod +x MultiCore-*.AppImage && ./MultiCore-*.AppImage` |

- **Служба.** Пакеты deb, rpm и Arch ставят и включают systemd-службу `multicore.service`: подключение мгновенное и без пароля. AppImage работает без службы — при подключении пароль спрашивает polkit (`pkexec`).
- **Трей.** Нужен StatusNotifierItem: KDE, GNOME с расширением AppIndicator, waybar, XFCE, Cinnamon, MATE.
- **AppImage.** Нужны GTK 3, polkit и AppIndicator. Ссылки `multicore://` AppImage не регистрирует, для кнопок «Добавить в MultiCore» ставьте пакет.

## Как добавить подписку

Любой из трёх способов:

1. **Скопировать ссылку и нажать «Вставить из буфера».**
2. **Ввести ссылку вручную** в поле подписки.
3. **Нажать кнопку «Добавить в MultiCore»** на странице подписки провайдера. Это ссылка вида `multicore://add/https://…`. Приложение покажет, с какого хоста пришла подписка, и спросит подтверждение.

MultiCore читает **не любую** подписку: провайдер должен отдавать конфиг для MultiCore. Обычные списки `vless://…` и base64-подписки не подходят. Если провайдер не поддерживает MultiCore, приложение прямо так и скажет. Провайдерам — в [документацию для провайдеров](docs/providers.md).

## Обновления

- **Когда проверяются.** Приложение смотрит последний релиз здесь при запуске и раз в сутки. Во время подключения обновления не ставятся.
- **Windows.** Скачивает `multicore-windows-x64.zip`, сверяет SHA-256 архива и каждого файла внутри, подменяет программу целиком и перезапускается. Если что-то пошло не так, откатывается на старую версию.
- **Windows со службой.** То же самое делает служба MultiCore: она сама скачивает и проверяет релиз, подменяет программу в `Program Files` и перезапускает приложение — без запроса прав.
- **AppImage.** Обновляется сам, прошлая версия остаётся рядом как `.old`.
- **deb / rpm / Arch.** Приложение только сообщает о новой версии, обновление ставите пакетным менеджером.

## Проверка файлов

В каждом релизе есть `RELEASE-SHA256SUMS.txt`. Сверить скачанный файл:

```powershell
# Windows
Get-FileHash .\MultiCore-Setup-x64.exe -Algorithm SHA256
```

```sh
# Linux
sha256sum -c --ignore-missing RELEASE-SHA256SUMS.txt
```

## Приватность

- **Мы ничего не собираем.** У проекта нет аккаунтов, телеметрии и аналитики, а наших серверов приложение не касается.
- **Что видит провайдер.** Приложение обращается только к ссылке, которую вы добавили. Провайдер получает стабильный идентификатор устройства (`x-hwid`, нужен для лимита устройств), ОС и её версию, модель устройства. Имя пользователя, имя компьютера и исходный MachineGuid не передаются.
- **Где лежат данные.** Подписки и настройки хранятся локально: `%LOCALAPPDATA%\MultiCore` на Windows, `~/.local/share/multicore` на Linux.
- **Ссылки подписок в логах.** В логи и диагностику ссылки не попадают.
